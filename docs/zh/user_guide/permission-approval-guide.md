# 权限审批使用指南

当 Agent 准备执行 Shell 命令或访问项目外的目录时，msagent 会根据操作类型、当前 Shell 审批模式和项目已有的授权决定是否需要确认。

## 选择 Shell 审批模式

在新项目里探索、排查问题或运行不熟悉的脚本时，选择 Manual（`manual`）。在可信项目中重复执行构建、测试或数据分析任务时，可以选择 Auto（`auto`），减少常规操作的确认。

| Agent 准备执行的操作 | Manual | Auto |
| --- | --- | --- |
| 可识别且没有写入输出的只读命令，例如 `git status` | 自动执行 | 自动执行 |
| 普通命令或直接运行脚本，例如 `python report.py` | 请求确认，已有匹配规则时按规则处理 | 默认执行，已有匹配规则时按规则处理 |
| 内联代码或可识别的动态执行形式，例如 `python -c` | 请求确认，已有匹配规则时按规则处理 | 默认执行，已有匹配规则时按规则处理 |
| 被识别为危险的命令，例如删除文件、提升权限或推送代码 | 每次确认 | 每次确认 |
| 被识别为禁止的命令 | 直接拒绝 | 直接拒绝 |
| 可识别的未授权外部目录访问 | 请求目录授权 | 请求目录授权 |

输入区的 `Shift+Tab` 切换的是 `--approval-mode` 对应的交互档位。Shell 的 Manual 和 Auto 由 `/permissions mode` 或 `--execute-approval-mode` 控制。

## 什么时候会看到提示

- **首次选择模式**。启动时未指定 Shell 审批模式、项目也没有保存模式时，交互式会话在第一次需要执行 Shell 命令时提示选择，并将选择保存到当前项目。
- **确认命令**。例如在 Manual 下首次运行 `python report.py`，如果没有适用的项目规则，就需要确认。即使启用 Auto，明确危险的命令仍需要确认。
- **授权目录**。例如 Agent 通过文件工具读取项目外的数据文件，或把 Shell 工作目录设为未授权的数据目录。目录获准后，Shell 命令仍按当前模式判断是否需要确认，因此一次操作可能先后看到目录授权和命令确认。拒绝目录授权会拒绝本次调用。

目录检查以当前工作目录和最近的 Git 工作树根目录为项目范围。可检查的路径包括文件工具的显式路径、Shell 的 `cwd` 或 `workdir`、明确的 `cd` 目标，以及能够可靠解析的命令路径参数。

## 在审批面板中选择授权范围

**Approve** 和 **Reject** 只作用于当前调用。仅当面板提供项目级选项时，才可保存规则。根据提示中的授权范围选择：

| 项目级规则 | 后续匹配范围 |
| --- | --- |
| 精确命令 | 相同的命令文本。面板提供长期拒绝选项时，也可保存拒绝规则。 |
| 命令族 | 同一种动态执行形式，例如 Python 内联代码，覆盖同族的不同代码内容。 |
| 项目脚本 | 同一解释器和规范化脚本路径。脚本参数和脚本内容变化后，规则仍可匹配。 |
| 外部目录 | 被授权的目录及其子目录。获准访问目录后，命令仍按自身的审批规则处理。 |

只有愿意持续信任相应的命令、代码或目录时，才选择 **Always allow**。在符合条件的 Manual 命令提示中选择 **Switch to Auto Mode**，会批准当前命令并为当前项目保存 Auto 模式。

## 查看、切换和撤销权限

在交互式会话中使用以下命令。

| 命令 | 用途 |
| --- | --- |
| `/permissions` | 查看当前生效的模式、模式来源和项目规则。 |
| `/permissions mode manual` | 将当前项目切换到 Manual。 |
| `/permissions mode auto` | 将当前项目切换到 Auto。 |
| `/permissions remove <rule-id>` | 按 `/permissions` 列出的 ID 撤销单条项目规则。 |
| `/permissions clear-project` | 清除当前项目保存的审批规则，保留 Shell 审批模式。 |
| `/permissions explain <command>` | 查看命令分类、匹配的规则和命令决策。该命令只分析命令本身。 |

也可以在启动时预设本次使用的模式，例如：

```bash
msagent --execute-approval-mode manual
msagent --execute-approval-mode auto "分析当前项目的测试结果"
```

启动时，显式参数优先于项目保存的模式。两者都未设置时，交互式会话在首次执行 Shell 命令时询问。项目模式和规则保存在 `~/.msagent/state/projects/<project-id>/config.approval.json`，同一项目的新进程和恢复的会话会继续读取，其他项目使用各自的设置。

## 常见问题

**为什么开了 Auto 还会询问？** 先看面板是在请求目录授权还是确认危险命令。可以用 `/permissions explain <command>` 查看命令决策。目录授权由工具调用的路径单独判断。

**为什么上次批准后这次还问？** 单次批准不会写入项目规则。若已选择项目级授权，用 `/permissions` 核对当前项目、规则类型和匹配范围。

**无人值守任务如何选择模式？** 用 `--execute-approval-mode` 预设模式可跳过首次选择。应事先在交互式会话中核对工作流和所需目录授权。任务如果需要人工确认，仍需要能接收审批输入的终端。

审批依据可识别的命令和显式路径。环境变量展开、动态代码和脚本内部访问可能无法被识别。获准的进程仍拥有运行 msagent 的操作系统用户权限，因此需要操作系统级隔离时，应由运行环境提供。
