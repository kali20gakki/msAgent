# 采集规模预算

## 预估公式

```
事件量 ≈ Σ_i(rate_i × cpus × duration_s)
         rate_i：该事件在目标核集上的单核事件率
                 空闲 20~50/s、中等 200~500/s、高负载 1~2K/s
DB 体积  ≈ 事件量 × 0.15KB
原始文本 ≈ 事件量 × 0.12KB
```

## 上限

| 维度 | 默认 | 上限 |
| ---- | ---- | ---- |
| 采集单位 | 单卡核集（A2 约 24 核） | ≤32 核（>32 视为非法输入） |
| 事件类型 | 标准档 8 类 | 10 类 |
| 单段时长 | 30s | 见下方矩阵 |
| 单段事件量 | 30 万 | 50 万 |
| 原始文本 | 65MB | 150MB |
| DB | 80MB | 200MB |
| 会话 | 单卡 1~2 段 | 10min（8 卡 × 60s） |

## 单段时长矩阵（按 50 万事件/段反推）

| 核集 | 最小档 | 标准档 | 扩展档 |
| ---- | ------ | ------ | ------ |
| ≤8 核 | 180s | 120s | 60s |
| 9~16 核 | 90s | 60s | 30s |
| 17~24 核 | 60s | 45s | 20s |
| 25~32 核 | 45s | 30s | 15s |

不建议 3min 作默认：事件量超预算、长窗混合多个 step、buffer 溢出风险与对比噪声同步上升。
3min 仅在「≤8 核 + 最小档 + 已按 tid/comm 收窄」时放开。

## 超限收窄顺序

```
① 收窄事件集（ext → std → min）
② 缩短单段时长 / 增加分段（段数 ≤6）
③ 缩小核集（仅 window/full 且非整卡核集；verify 不可减核）
④ 拒绝采集，输出预算明细，提示改 verify 模式或逐卡执行
```

## 各模式基线

| 模式 | 核集 | 事件档 | 单段 | 预估 |
| ---- | ---- | ------ | ---- | ---- |
| verify | 单卡 24 核 | min | 10s | 约 4.8 万事件 / 7MB |
| window | 单卡 ≤16 核 | std | 窗长 ≤30s | 2~35MB |
| full | 单卡 24 核 | std | 30s | 20~150MB |

预算结果写入 DB `meta.budget`，实测写入 `meta.budget_actual`；触顶截断标 `meta.truncated=true`。
